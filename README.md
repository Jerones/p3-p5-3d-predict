# 排列三 · 福彩3D · 排列五 分析预测（p3-p5-3d-predict）

基于新浪彩票走势图历史开奖数据的分析与当日预测工具：三彩种（排列三、福彩3D、排列五）走势统计、当日预测、近 10 期回测复盘、历史预测存档，以及他人计划表的补充交叉预测。

> 理性购彩提示：开奖为独立随机事件，本项目所有预测仅供走势统计参考，不保证命中。计划表交叉仅作补充参考，**不绝对正确**。

## 功能

- **走势分析（近 120 期）**：冷热号、当前遗漏、分位走势与 012 路、和值/跨度分布、奇偶/大小比、组三/组六形态（排列五为五位定位与数字个数分布）。
- **当日预测**：胆码、杀号、直选定位（每位候选）、组选池、直选精选（3 位彩种 8 注、排列五 12 注，和值/跨度区间内优先）、和值/跨度推荐区间。
- **复盘（近 10 期回测）**：胆码逐个标注命中 ✓/未中 ✗；定位按位展开（列出每位候选、开奖数、在/不在候选）；杀号逐个标注杀对 ✓/杀错 ✗；和值/跨度显示预测区间 + 实际值 + ✓/✗；直选精选给出命中率（整注完全相等才算直选命中）以及每注的**位对**（同位置对上的个数）与**数对**（不看位置、按数字多重集 min 交集计数），数字全对但顺序错的单独分类（组选对、直选未中）。
- **历史预测存档**：预测首次生成即写入 `data/snapshots.json`，按「彩种 + 目标期号」唯一，**已存档不覆盖**；刷新在新开奖入库前先存档 outgoing 期。页面有「当日预测 / 历史预测」切换，可按期号回看存档预测及其开奖复盘。
  - `data/snapshots.json` 中含一份 **2026282 期排列三已知快照种子**（基于 2026281 期，胆码 1 9 0、杀号 8 4 5、组选池 1 9 0 3 7 6、直选精选 135 170 175 339 035 075 395 370、和值 8-17、跨度 4-7），明确标注为种子示例（`seed: true`），且其定位候选原始数据未提供、为空。
- **计划表交叉**：在网页粘贴或上传 CSV/TXT 计划表，解析推荐号/胆码/杀号后与主模型交叉——重合的出共识胆码与交叉精选，撞主模型杀号或计划表自身杀号的进入风险组。全程标注仅参考、不绝对正确。
- **每日自动刷新**：每天 22:00（开奖后，Asia/Shanghai）抓取当天开奖、存档复盘、生成次日预测；页面也有手动刷新按钮。

## 快速开始

需要 Node.js ≥ 18（零第三方依赖）。

```bash
npm run fetch   # 抓取新浪走势图 2026 年开奖数据，写入 data/draws.json
npm start       # 启动服务，打开 http://localhost:5173
```

`data/draws.json` 结构：

```json
{
  "source": "新浪彩票走势图 …",
  "fetchedAt": "ISO 时间",
  "note": "本次实际抓取情况说明",
  "errors": {},
  "draws": {
    "p3": [{ "issue": "2026001", "nums": [8, 3, 0] }],
    "p5": [{ "issue": "2026001", "nums": [8, 3, 0, 0, 0] }],
    "3d": [{ "issue": "2026001", "nums": [0, 0, 0] }]
  }
}
```

（上例仅为格式示例，不代表真实开奖。）抓取失败时 `draws` 对应彩种为空数组，`note`/`errors` 与运行日志会如实标注，页面会提示暂无数据，不会伪造开奖数据。

## 数据来源

新浪彩票走势图：`https://view.lottery.sina.com.cn/lotto/pc_zst/index`

| 彩种 | lottoType | actionType |
| --- | --- | --- |
| 排列三 | `p3` | `jqzs`（直选形态） |
| 排列五 | `p5` | `chzs`（基本走势） |
| 福彩3D | `3d` | `jqzs`（直选形态） |

参数 `year=2026&dpc=1`。抓取脚本解析页面表格中的期号与开奖号单元格，写出 `data/draws.json`。

## 定时刷新

- **GitHub Actions（已内置）**：`.github/workflows/refresh.yml` 每天 22:00（Asia/Shanghai，即 14:00 UTC）运行 `npm run fetch`，若 `data/draws.json` 有变化则自动 commit 回仓库（workflow 已声明 `permissions: contents: write`）。注意：Actions 运行时是无状态的，服务在 Actions 里生成的预测存档不会回写；存档以本地/服务器运行时写入的 `data/snapshots.json` 为准，如需把存档也纳入版本管理，可自行扩展 workflow 提交 `data/` 整个目录。
- **服务器 cron 方案**：在部署服务器上添加例如 `0 22 * * * cd /path/to/repo && npm run fetch`（按服务器时区设置），再重启/刷新服务即可。

## 部署说明与限制

- **部署到服务器**：把仓库克隆到服务器，`npm run fetch && npm start`（或用 pm2/systemd 常驻，环境变量 `PORT` 可改端口），配合上面的 cron 即可保留自动刷新与存档写入。
- **GitHub Pages**：Pages 只能托管静态文件，不能运行 `server.js` 的 API 与存档写入。若只想展示，可把 `public/` 配合一份静态 `draws.json` 自行改造为纯前端版本，但将失去：计划表交叉的服务端计算（可改为前端计算）、预测存档落盘、自动刷新。本仓库默认提供的是可完整运行的 Node 版本，请优先部署到服务器。
- 本项目为独立实现，与任何在线服务无关；数据抓取依赖新浪页面结构，页面改版时需同步调整 `lib/fetch-sina.mjs` 的解析规则。
